Membangun High Availability Cluster dengan Kubernetes

15 Jan 2025
12 min read
Firman Hidayatuloh Engineer
24.3K reads

Kubernetes telah menjadi standar industri untuk orchestration container, namun implementasi production-ready membutuhkan pemahaman mendalam tentang High Availability (HA). Dalam panduan ini, kita akan membahas arsitektur dan konfigurasi cluster Kubernetes yang tahan terhadap kegagalan node dan dapat melayani jutaan request tanpa downtime.

Mengapa High Availability Penting?

Setiap detik downtime dapat mengakibatkan kerugian finansial signifikan. Cluster HA dirancang untuk memastikan service tetap berjalan meskipun terjadi kegagalan hardware, network partition, atau maintenance. Dengan redundansi di setiap level—master node, worker node, dan storage—sistem dapat melanjutkan operasi normal tanpa gangguan.

Arsitektur HA Kubernetes

Cluster HA memerlukan minimal 3 master node untuk toleransi fault (quorum etcd). Setiap master menjalankan API Server, Scheduler, dan Controller Manager. Load balancer di depan master node memastikan request terdistribusi dan failover otomatis ketika satu master down.

# Konfigurasi load balancer untuk master nodes (contoh HAProxy) listen kubernetes-master bind 0.0.0.0:6443 balance roundrobin server master1 10.0.1.10:6443 check server master2 10.0.1.11:6443 check server master3 10.0.1.12:6443 check

Persiapan Infrastructure

Mulai dengan provisioning minimal 3 master node dan minimal 3 worker node. Setiap node harus memiliki:

  • Minimum 2 CPU core per master, 1 CPU per worker
  • Minimum 4GB RAM per master, 2GB RAM per worker
  • Network bandwidth tinggi (minimum 100Mbps)
  • Storage terpisah untuk etcd pada master node

Instalasi dan Konfigurasi Cluster

Gunakan tools seperti kubeadm untuk bootstrap cluster. Untuk HA, konfigurasikan external etcd cluster terlebih dahulu sebelum menginisialisasi master node pertama. Ini memisahkan fault domain dan memudahkan scaling master nodes.

# Inisialisasi master node pertama dengan external etcd kubeadm init --control-plane-endpoint="LB_IP:6443" \ --upload-certs \ --pod-network-cidr=10.244.0.0/16 \ --service-cidr=10.96.0.0/12 \ --etcd-external-urls=https://etcd1:2379,https://etcd2:2379,https://etcd3:2379

Strategi Storage dan Backup

Implementasikan persistent volume dengan replication factor 3 menggunakan Ceph, GlusterFS, atau cloud-native storage solutions. Backup etcd secara regular setiap jam untuk disaster recovery. Simpan backup di lokasi geografis berbeda untuk proteksi maksimal.

Monitoring dan Alerting

Deploy Prometheus dan Grafana untuk monitoring real-time. Setup alert untuk kondisi kritis seperti node tidak healthy, pod crash loop, atau storage pressure. Dengan visibility sempurna, tim dapat merespons issue sebelum berdampak ke end user.

Testing Failover

Lakukan chaos engineering testing secara regular. Simulasikan kegagalan master node, network partition, dan storage failure. Verifikasi bahwa traffic otomatis redirect ke node sehat dan tidak ada data loss.

Kesimpulannya, membangun Kubernetes HA membutuhkan planning matang dan testing ekstensif. Dengan mengikuti best practices ini, Anda memiliki infrastructure yang robust dan siap production dengan tingkat availability mencapai 99.99%.
